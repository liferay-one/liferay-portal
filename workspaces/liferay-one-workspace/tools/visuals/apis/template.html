OAuth2 Scopes

Each Liferay API that the sidecar calls, the scope it needs, and the sidecar OAuth2 application that declares it. A scope that no call needs is listed as unused.

Generated by tools/visuals/apis from liferay-one-custom-element/src, the route= placements in liferay-one-site-initializer, and the mapping annotations in liferay-one-etc-spring-boot.

The scopes come from every client-extension.yaml and from the /o/ paths and generated headless clients in the sidecar source. A scope that ends in .read covers reads only, and the scan does not check whether a call writes. It also cannot tell which token a call uses, so a scope counts as declared when any sidecar application declares it.

The caller check is what the handler reaches: a com.liferay.one.permission class, a signature validator, hasAccountMembership, or a PrincipalException, in the handler or in a private method of its class. It shows that a check runs, not that the check is correct. A check of the wrong ID, or a check that trusts a forged token, still reads as a check. Those defects are in the Go-Live Tasks artifact.

The scan is static. A route reaches a declaration when code it already reaches names it, and a class method when any reached code names the method, so a common method name can add a call that the route never makes. Calls inside packages, fragments, and liferay-one-etc-cron are not read. A listed call can run from the route, for example from a button. It does not run on every page load.
