Workspace Health

Everything to act on in the workspace. The Model, View, and Controller pages show what the code is. Each problem, known defect, and finding that they report comes here, sorted by layer, with the actions that span the layers: the dependencies, the tests, the change hotspots, and the specs. An action that no ticket or audit ID tracks is in the triage queue.

Generated by tools/visuals/workspace-health. A problem fails yarn viz:check. A known defect is listed in known-defects.json with its ticket or audit ID. A finding comes from a visual's own input or scan. An action is tracked when a known defect gives its reason, or when its text names a ticket or a Go-Live Tasks ID.

The dependency section reads the package.json files, yarn.lock, and the build.gradle of each client extension, and the snapshot that yarn viz:deps writes. The tests section reads the test sources and the run history that yarn viz:tests records. The changes section reads git log. The specs section checks the names in backticks in specs/ against the code. yarn viz:diff marks the actions that the current branch adds to its base.
